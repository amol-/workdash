Keep the same work visible

Let an agent or script inspect and act on the same work you see.

You keep visibility into the panes where your agents work. You can step into the same pane whenever you need to participate.

  1. Pick a work item. Use workdash list to choose an issue.
  2. Start your chosen agent. Run workdash code ITEM --agent NAME to launch it in the work item's worktree.
  3. Stay in the conversation. Read the agent's pane and send input, or continue directly in the pane yourself.
  4. Review the result. Inspect the changes before you decide what to merge.

Text as the connection

Coordinate through text while you keep your agents, editors, and terminal tools independent.

Unix pipes inspire this approach: independent tools share text instead of belonging to one application. Zellij carries text into and out of panes, rather than turning panes into literal Unix pipes. You and workdash see the same terminal output.

You configure compatible command-line agents for analysis and coding. Text-driven tools need no Workdash-specific plugin, extension, or dedicated harness for pane interaction. Your tools still determine how they interpret input and display output.

The CLI is the interface

Use the same commands yourself or let an agent or script call them for you.

Add --json when your caller needs machine-readable output.

CommandPurpose--json
workdash listList the dashboard's current work items.Yes
workdash ready SCOPEFind issues ready to pick up next.Yes
workdash infoInspect live Workdash panes and dispatch sessions.Yes
workdash dispatch SCOPELaunch one ready issue.Yes
workdash autodispatch SCOPEStart a dispatch loop for your chosen scope.Yes
workdash autodispatch-stop SESSION_IDStop a dispatch session.Yes
workdash analyze ITEMGet a cached or fresh analysis of a work item.Yes
workdash review ITEMStart an agent review of an open PR.Yes
workdash code ITEMLaunch a coding agent or report the running one.Yes
workdash terminal ITEMOpen a terminal in a work item's worktree.Yes
workdash todo TEXTCapture a todo, or close one with workdash todo --close ITEM.Yes

Start workdash before you use server-backed commands. Only workdash show-config in this table works without a running server.

Talking to a live pane

Read what your agent prints and send input without leaving the shared work.

Use workdash info to find the pane ID you want. workdash read PANE_ID reads its visible text. workdash write PANE_ID TEXT sends your text followed by Enter.

If your agent's pane ID is terminal_23, you can use:

workdash read terminal_23
workdash write terminal_23 "Explain the changes before you continue."
workdash read terminal_23

Add --full to workdash read when you need the pane's scrollback. You can also open the same pane in Zellij and interact directly.

Give your agent CLI guidance when it needs help choosing commands and following work.

The supplied workdash-control skill explains how your agent uses the CLI. You do not need the skill as an integration or a dedicated harness. Your agent can use the commands directly.

Connect beyond localhost

Connect CLI clients to your running server from another machine on a trusted network.

Add listens entries in ~/.config/workdash/config.json to accept network connections. Each entry names a listening address followed by accepted source IPs or CIDR subnets. 

"listens": ["192.168.1.5@192.168.1.10,192.168.2.0/24"]

Here your server listens on 192.168.1.5 using its selected port. Your accepted sources include 192.168.1.10 and the 192.168.2.0/24 subnet. Accepted sources apply across your listeners.

Use --host HOST[:PORT] per server-backed command to select your running server. You can omit the port to use 8765. 

workdash list --json --host dashboard.lan
workdash info --host dashboard.lan:8765

Your CLI clients connect without local GitHub credentials, configuration, or Zellij state. Keep your dashboard state, worktrees, credentials, Zellij session, and agent tooling together on the server host. workdash show-config reports your local configuration and does not accept --host.

Trusted network only

Keep the control server off untrusted networks.

Your connection uses plain HTTP with no authentication. The IP allowlist is not a security boundary or a substitute for authentication and encryption. An accepted client can execute dashboard actions. Do not expose the server to untrusted networks.

Resume your remote session

Reach the terminal on your development machine when you want to use the dashboard directly.

  • Attach to your session. Connect over ssh and attach to your existing Zellij session.
  • Keep your workspace together. Your worktrees and tools remain on your development machine while you interact from another device.
  • Distinguish chat from remote access. The assistant chat screenshot shows conversation, not a remote terminal connection.
